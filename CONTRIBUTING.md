# Contributing to rdf-augmenter

Thanks for your interest in improving rdf-augmenter! The goal of this project is
to be reusable research infrastructure for RDF knowledge graph augmentation, so
contributions that increase scientific usefulness, reproducibility, and
educational value are especially welcome.

## Ways to contribute

- **New backends.** Implement the `Backend` interface (`suggest(term,
  relation_type, top_k)`) for a new augmentation method and add it to
  `rdf_augmenter/backends.py`.
- **Lexicons.** Contribute curated domain lexicons (biomedical, legal,
  scientific, multilingual) under `rdf_augmenter/data/` or as separate files.
- **Benchmark datasets & tasks.** Loaders for DBpedia, Wikidata, YAGO, Bio2RDF,
  and evaluation tasks (link prediction, entity classification, QA).
- **Tutorials & notebooks.** Runnable educational material.
- **Bug reports & fixes.** See the issue templates.

## Development setup

```bash
git clone https://github.com/jorge-martinez-gil/rdf-augmenter.git
cd rdf-augmenter
pip install -e ".[dev]"
pytest                      # run the test suite
```

## Guidelines

- **Keep the core lightweight.** The base install must depend only on `rdflib`.
  Heavy dependencies (torch, transformers, nltk, pyshacl) belong in optional
  extras.
- **Determinism by default.** New backends should be reproducible given a seed,
  or clearly document when they are not.
- **Scientific integrity.** Never commit fabricated benchmark numbers. Results
  must be generated by reproducible code and traceable to a manifest.
- **Add a test.** New functionality should come with a `pytest` test.
- **Document it.** Update the relevant tutorial, the concepts glossary, or the
  README when you add a capability.

## Submitting changes

1. Fork the repository and create a feature branch.
2. Make your change with tests and docs.
3. Ensure `pytest` passes.
4. Open a pull request describing the motivation and the change.
